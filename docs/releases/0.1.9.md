# UnifiedVPN 0.1.9

Build: `2026111301`.

## Changes

- Android and Windows can import and run VMess and Hysteria2 profiles through the existing pinned Xray core. Hysteria2 also accepts the `hy2://` alias. Protocols are dispatched to their actual outbound implementations.
- The QR scanner and `unifiedvpn://import?url=…` links accept HTTPS subscription URLs on the subscription's own host, including custom ports and query parameters. Existing subscription URLs and stored profile identities are preserved on refresh.
- Base64-encoded JSON subscriptions containing one AWG or RTC profile are accepted. A selected-profile subscription can contain up to 16 profiles.
- VMess and Hysteria2 credentials are redacted from support logs. TLS certificate verification remains required; unsupported options are rejected instead of silently enabling insecure TLS.

## Supported new profile formats

VMess: standard Base64 share JSON in a `vmess://` URI, or share JSON in a typed subscription entry. Modern `alterId=0` is required. Supported transports: RAW/TCP, WebSocket, gRPC, HTTPUpgrade, and XHTTP.

Hysteria2: `hysteria2://` / `hy2://` URIs, or a typed JSON profile with `server`, `auth`, optional `name`, and optional `tls.sni`. Salamander obfuscation, certificate pins, port hopping, and insecure TLS are not supported by this client implementation.

Importing a profile requires a matching server listener. Adding a client protocol does not enable that protocol on a server or guarantee availability on a particular mobile network.

Native engine versions are unchanged from 0.1.8. Source changes do not replace the active VPN used by the build computer. Windows connectivity tests use an isolated local SOCKS listener; they do not change the system proxy or enable TUN.

Android updates require the same application ID and signing certificate, with a higher version code.
