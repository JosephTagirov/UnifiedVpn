# Unified VPN 0.0.14 Build 2026101301

## English

Android and Windows x86-64 release. VK Calls remains experimental; other engines
are not replaced by the VK fork. This is a newer build of 0.0.14, not 0.0.15.

### Changes

- Added VK Calls as an olcRTC provider with VP8 and the Chrome-compatible DTLS
  profile. Its pinned native engine is packaged separately from Jitsi.
- Android VK uses the existing VPN service, authenticated local SOCKS and the
  shared olcRTC/OpenFlux split-tunneling rules. Startup retries, cancellation,
  Stop and removal of temporary configuration are bounded.
- Windows VK supports local SOCKS and system proxy. Readiness requires the
  authenticated native handshake and SOCKS credentials, not just an open port.
- Includes the intervening Android Jitsi certificate-store correction and
  startup fixes. Jitsi remains on `d7a00da5242f`; its three native Android
  libraries are unchanged from build 2026101102.
- Includes OpenFlux Session profiles and the classic browser-bootstrap fixes.
  Classic `yandex`/`vyandex` configurations are not converted to Session format.
  Changes in Yandex access/editor behavior can still prevent a connection.
- AWG 3.1 and the existing VLESS/Xray integrations are retained. No server
  configuration, private profile or account credential is shipped in the app.

### Verification

- 410 JVM tests and 304 Android host tests passed, plus four focused native suites.
- The final packaged Windows manager/core and the exact signed APK on an
  Android API 35 emulator reached VK Connected, passed certificate-verified
  HTTPS to Instagram/Wikipedia and stopped cleanly.
- JVM launch, bundled assets, MSI upgrade/preflight metadata and all 251 portable
  files were checked. See the [full test report](../testing/vk-calls-2026101301.md).
- Physical Android 13, direct Megafon whitelist operation, sustained speed,
  simultaneous clients, Windows installation over an existing copy and Windows
  TUN traffic/recovery were not validated in this session. FI_2/FI_3 were not
  live-tested again; this is not a claim that every retained transport works.
- Windows VK TUN and Android inactive VK latency probing are not implemented.

Previous assets and the historical `v0.0.14` source tag are retained. The

compares both 0.0.14 and the asset build number. An older application that does
not support MSI updates must install the MSI manually. Windows binaries are not
Authenticode-signed; do not disable antivirus or TLS verification. Android
keeps the previous signing identity. System installation confirmation remains
required. Profiles and keys must be supplied privately, not through the release.

## Русский

Выпуск для Android и Windows x86-64. VK Calls остаётся экспериментальным;
его форк не заменяет остальные ядра. Это новая сборка 0.0.14, не версия 0.0.15.

### Изменения

- Добавлен провайдер olcRTC VK Calls: VP8 и совместимый с Chrome профиль DTLS.
  Зафиксированное VK-ядро упаковано отдельно от Jitsi.
- Android VK использует существующую VPN-службу, локальный SOCKS с авторизацией
  и общие правила раздельного туннелирования olcRTC/OpenFlux. Ограничены повторы
  запуска, отмена, остановка и удаление временной конфигурации.
- В Windows VK доступны локальный SOCKS и системный прокси. Готовность требует
  аутентифицированного рукопожатия ядра и проверки SOCKS, не просто открытого порта.
- Включены исправление хранилища сертификатов Android Jitsi и доработки запуска
  промежуточных сборок. Jitsi остаётся на `d7a00da5242f`; три Android-библиотеки
  побайтно совпадают со сборкой 2026101102.
- Включены профили OpenFlux Session и исправления классической браузерной
  проверки. Старые `yandex`/`vyandex` не преобразуются в Session автоматически.
  Изменения доступа и редактора Яндекса всё ещё могут мешать подключению.
- Сохранены AWG 3.1 и существующая интеграция VLESS/Xray. Приложение не содержит
  серверных настроек, приватных профилей и учётных данных.

### Проверки

- Пройдены 410 JVM-тестов, 304 Android host-теста и четыре набора тестов ядра.
- Итоговые manager/ядро Windows и точный подписанный APK в эмуляторе Android
  API 35 достигли VK Connected, передали HTTPS к Instagram/Wikipedia с проверкой
  сертификатов и штатно остановились.
- Проверены запуск JVM, встроенные файлы, метаданные обновления/предварительных
  проверок MSI и все 251 файл portable. Есть [полный отчёт](../testing/vk-calls-2026101301.md).
- В этой сессии не проверены физический Android 13, прямое подключение при белых
  списках Мегафона, длительная скорость, одновременные клиенты, установка Windows
  поверх прежней копии и трафик/восстановление Windows TUN. FI_2/FI_3 не проходили
  повторную живую проверку; работа каждого сохранённого транспорта не гарантируется.
- Windows TUN для VK и пинг неактивного VK-профиля на Android не реализованы.
