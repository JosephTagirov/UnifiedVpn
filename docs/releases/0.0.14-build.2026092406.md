# Unified VPN 0.0.14 Preview

Build **2026092406** for Android and Windows x86-64. Experimental prerelease,
installed manually; the stable update channel remains on 0.0.12.

## Changes

- OpenFlux now explicitly supports both classic Yandex Documents (`yandex`) and
  the new Volga text editor (`vyandex`). Manual entry, editing, import and sharing
  retain the selected transport. Existing profiles are not silently converted.
- OpenFlux wrapper 5 requires authenticated AES-256-GCM on both peers. Bounded,
  anonymous browser verification does not reuse personal browser sessions.
  Startup cancellation and expired-session handling have been fixed.
- Android notification profile selection stays synchronized with the main app.
  The chooser stays open after failure/Stop and offers Reconnect. Its app icon
  opens Unified VPN. OpenFlux and olcRTC retain shared per-app split rules.
- OpenFlux supports QR/link sharing with a secret-key warning and HTTPS latency
  checks through the matching active tunnel. Each simultaneous device needs a
  separate document, key and server instance.
- The AWG-capable core includes AWG 3.1 options and the reserved-byte fix.
  olcRTC stays on the previously verified server-compatible `d7a00da` revision;
  no automatic server upgrade is performed.
- Windows VLESS/AWG routing is separate from olcRTC/OpenFlux. The experimental
  VLESS/AWG TUN helper requests administrator consent; the app itself runs normally.

## Verified And Limited

- The exact packaged Windows app passed authenticated OpenFlux Local SOCKS,
  certificate-verified HTTPS to Instagram and Telegram, a 25-second repeat and
  clean stop on two separate Volga profiles, without changing the host network.
- The unchanged signed release APK passed real UI Start, Android VPN consent,
  authenticated OpenFlux, TUN, strict HTTPS to Instagram/Wikipedia and UI Stop
  in fresh Android API 35 emulators on both separate profiles.
- AWG 3.1 passed real traffic on Windows Local SOCKS and the exact Android release
  in an emulator, with separate device keys, rekeying and clean stop.
- Native, profile/import, browser-policy, packaging and server-tool tests passed.
  See the [build-specific report](https://github.com/JosephTagirov/UnifiedVpn/blob/v0.0.14/docs/testing/openflux-volga-2026092406.md)
  for artifact identities and test scope.
- These are bounded tests, not a guarantee of uninterrupted service. Physical
  Android devices, sustained throughput, independent leak analysis and Windows
  TUN traffic/UAC/crash recovery are not fully validated. Earlier direct VLESS
  network failures are not declared fixed by this release.
- Windows olcRTC/OpenFlux remain Local SOCKS/System proxy only. OpenFlux carries
  TCP/IPv4, not general UDP/IPv6. A compatible encrypted server is required;
  a Yandex document link alone is not an importable VPN configuration.

# Unified VPN 0.0.14: Предварительный Выпуск

Сборка **2026092406** для Android и Windows x86-64. Экспериментальная версия
устанавливается вручную; стабильный канал обновлений остаётся на 0.0.12.

## Изменения

- OpenFlux явно поддерживает прежний редактор Яндекс Документов (`yandex`) и новый
  текстовый редактор Volga (`vyandex`). Ручной ввод, редактирование, импорт и экспорт
  сохраняют выбранный транспорт. Старые профили автоматически не преобразуются.
- Обёртка OpenFlux 5 требует аутентифицированное AES-256-GCM с обеих сторон.
  Ограниченная анонимная браузерная проверка не использует личные сессии браузера.
  Исправлены отмена запуска и обработка недействительной сессии.
- Выбор профиля в шторке Android синхронизирован с главным экраном. Окно остаётся
  открытым после ошибки/Stop и предлагает переподключение; значок открывает
  приложение. У OpenFlux и olcRTC общие правила раздельного туннелирования.
- OpenFlux поддерживает QR/ссылки с предупреждением о секретном ключе и HTTPS-пинг
  через соответствующий активный туннель. Для одновременных устройств нужны разные
  документы, ключи и серверные экземпляры.
- AWG-ядро поддерживает параметры AWG 3.1 и исправление reserved bytes. Для olcRTC
  сохранена проверенная совместимая с сервером ревизия `d7a00da`; автоматического
  обновления серверов нет.
- У Windows VLESS/AWG отдельные от olcRTC/OpenFlux настройки маршрутизации.
  Экспериментальный TUN-компонент запрашивает права администратора; само приложение
  следует запускать обычным способом.

## Проверки И Ограничения

- Точное собранное Windows-приложение прошло OpenFlux Local SOCKS, HTTPS с проверкой
  сертификатов к Instagram/Telegram, повтор через 25 секунд и остановку на двух
  отдельных Volga-профилях. Сетевые настройки Windows не менялись.
- Неизменённая подписанная релизная APK прошла запуск через интерфейс, разрешение
  Android VPN, зашифрованное OpenFlux-подключение, TUN, HTTPS к Instagram/Wikipedia
  и остановку в новых эмуляторах Android API 35 на обоих профилях.
- AWG 3.1 прошёл реальный трафик на Windows Local SOCKS и в эмуляторе с точной
  релизной APK: разные ключи устройств, обновление сессионных ключей и остановка.
- Пройдены тесты ядер, профилей/импорта, браузерных ограничений, упаковки и серверных
  инструментов. Хеши и объём проверок указаны в [отчёте этой сборки](https://github.com/JosephTagirov/UnifiedVpn/blob/v0.0.14/docs/testing/openflux-volga-2026092406.md).
- Это короткие проверки, а не гарантия непрерывной работы. Физические телефоны,
  длительная нагрузка, независимая проверка утечек и Windows TUN/UAC/аварийное
  восстановление проверены не полностью. Прежние сетевые сбои прямого VLESS
  этим выпуском не объявляются исправленными.
- Для Windows olcRTC/OpenFlux доступны Local SOCKS и системный прокси. OpenFlux
  передаёт TCP/IPv4, не произвольный UDP/IPv6. Нужен совместимый зашифрованный
  сервер; одна ссылка документа Яндекса ещё не является VPN-конфигурацией.

## Загрузка

В таблице выше приложены Android APK, установщик Windows EXE, исходники встроенных
OpenFlux/AWG, уведомления о лицензиях и `SHA256SUMS.txt`. EXE не подписан
Authenticode: Windows может показать неизвестного издателя или SmartScreen.
Не отключайте антивирус. APK сохраняет прежнюю подпись для совместимости обновлений.
Приватных профилей, ссылок документов, ключей, cookies и доступа к серверу нет.
Нового Linux-бинарника и нового админского инструмента выдачи профилей в этом
выпуске приложения нет.

В основе находится оригинальный [olcbox Алана Анисимова](https://github.com/alananisimov/olcbox).
Используются olcRTC, OpenFlux, Throne sing-box, AmneziaWG и Xray-core, ссылки и
лицензии сохранены выше. Исходники приложения соответствуют тегу `v0.0.14`.
