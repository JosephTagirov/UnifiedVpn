# Unified VPN 0.0.13, Build 2026091401

**Experimental preview, not the stable update.**
The stable update channel remains on 0.0.12. Install this preview manually only
after reading the limitations below. Windows and Android emulator OpenFlux
connections passed real HTTPS checks on 2026-09-15.

## Changes

- Experimental encrypted OpenFlux over Yandex Documents, with mandatory
  AES-256-GCM and an authenticated peer handshake, without plaintext fallback.
- Visible `+ -> Add OpenFlux` action and manual document URL/encryption-key fields;
  OpenFlux URI/JSON import, editable names, and scrollable forms.
- Android has one shared **olcRTC / OpenFlux** per-app split-tunneling group.
  Existing lists remain intact. VLESS/AWG keep their separate group. These rules
  apply to Android VPN mode; proxy mode does not apply per-app exclusions.
- Notification profile switching and rollback refresh saved split-tunneling
  rules. Cancellation and preference-read errors do not silently replace them
  with all-app routing.
- The icon beside `Ping` is a lightning bolt; the progress indicator is retained.
- Combined-profile restore preserves supported non-olcRTC profiles. Diagnostics
  redact OpenFlux document links and encryption keys.
- Pinned native packaging, transport/process tests, opt-in isolated server
  tooling, and a bounded Windows throughput benchmark.
- Android reports a clear error if VPN preparation is missing or revoked.
  The debug test entry point now prepares VPN ownership before starting it.

## Validation And Limits

- Passed 234 offline JVM tests, 164 Android host tests, 111 synthetic Android
  harness checks, and 17 stdin/checksum tests. Native transport/session and
  Python profile/server tooling tests also passed.
- Windows passed encrypted OpenFlux readiness, authenticated SOCKS, real external
  HTTPS, a 25-second liveness repeat, and clean shutdown on current code. The
  four-protocol Windows download samples are in the [historical report](../testing/openflux-0.0.13.md).
  These are not Android throughput measurements or guarantees of availability.
- Android 35 x86_64 passed authenticated OpenFlux, system TUN, TLS-verified
  Instagram/Wikipedia HTTP 200, stable app/core/DNS-bridge processes, and clean
  stop in a fresh isolated emulator. Live instrumentation used the debug APK
  with the same runtime code; it is not a physical-phone or carrier test.
- The release APK is non-debuggable, its signing certificate matches 0.0.12,
  and three ABI/native contents and alignment were verified. The packaged
  Windows EXE passed JVM/native-assets smoke and compiled MSI upgrade-policy
  checks. See the [current validation report](../testing/openflux-2026091401.md).
- The signed Android release passed offline Add OpenFlux/editor, keyboard
  scrolling and split-rule selector navigation without an app crash.
- Live checks use a single connection slot, isolated application data, and
  sequential clients; existing server/document settings are not changed.
- One active client per document/key/server instance, with the legacy Yandex
  editor. Both ends require the matching `unified-openflux-aesgcm-v1` wrapper.
  Unmodified upstream OpenFlux is not interchangeable with this wrapper.
- TCP/IPv4 only; no general UDP or IPv6. Destination DNS uses encrypted TCP;
  transport bootstrap uses the underlying network. No forward-secrecy or full
  security-audit claim is made.
- Windows TUN remains unavailable. Local SOCKS and System proxy are available.
  New physical-device and installation-over-the-working-Windows-copy checks
  have not been performed. Windows Authenticode signing is not configured.
- Existing stable-release limitations, including intermittent Android VLESS
  startup DNS/TLS failures, are not declared fixed by this preview.

# Unified VPN 0.0.13, Сборка 2026091401

**Экспериментальная предварительная версия, не стабильное обновление.**
В стабильном канале остаётся 0.0.12. Устанавливайте эту версию вручную только
после ознакомления с ограничениями. Подключения OpenFlux на Windows и
Android-эмуляторе прошли реальные HTTPS-проверки 2026-09-15.

## Изменения

- Экспериментальный OpenFlux через Яндекс Документы: обязательный AES-256-GCM,
  аутентификация соединения, без передачи открытым текстом.
- Отдельное действие `+ -> Добавить OpenFlux`, ручной ввод ссылки документа и
  ключа шифрования, импорт URI/JSON, редактирование названия и прокрутка формы.
- На Android одна общая группа раздельного туннелирования **olcRTC / OpenFlux**.
  Прежние списки сохраняются. VLESS/AWG остаются отдельной группой. Правила
  действуют в Android VPN-режиме; в режиме прокси исключения приложений не применяются.
- Переключение и возврат через уведомление перечитывают сохранённые правила.
  Отмена и ошибка чтения не заменяют их молча туннелем для всех приложений.
- Рядом с `Пинг` теперь молния, индикатор выполнения сохранён.
- Восстановление общего пакета сохраняет поддерживаемые не-olcRTC профили.
  Ссылки документов и ключи OpenFlux скрываются в диагностике.
- Проверки закреплённых native-файлов, тесты транспорта/процессов, отдельные
  серверные инструменты и ограниченный замер скорости Windows.
- Android сообщает об ошибке, если подготовка VPN отсутствует или отозвана.
  Тестовый вход теперь подготавливает владельца VPN перед запуском.

## Проверки И Ограничения

- Прошли 234 офлайн JVM-теста, 164 Android host-теста, 111 синтетических проверок
  Android-сценария и 17 тестов stdin/контрольных сумм. Также прошли нативные тесты
  транспорта/сеанса и Python-тесты профилей и серверных инструментов.
- Текущий Windows-код прошёл зашифрованную готовность OpenFlux, SOCKS с
  авторизацией, реальный HTTPS, повторную проверку через 25 секунд и остановку.
  Замеры четырёх протоколов Windows есть в [историческом отчёте](../testing/openflux-0.0.13.md).
  Это не скорость Android и не гарантия доступности.
- Android 35 x86_64 прошёл аутентификацию OpenFlux, системный TUN, проверенный
  TLS и HTTP 200 от Instagram/Wikipedia, контроль неизменности процессов и
  корректную остановку на отдельном чистом эмуляторе. Реальный сетевой тест
  использовал debug APK с тем же runtime-кодом; это не проверка телефона или оператора.
- Релизный APK не отладочный, сертификат совпадает с 0.0.12; состав трёх ABI,
  native-файлы и выравнивание проверены. Windows EXE прошёл запуск JVM,
  проверку встроенных движков и политики обновления MSI. См.
  [текущий отчёт](../testing/openflux-2026091401.md).
- Подписанный Android APK также прошёл офлайн-проверку добавления OpenFlux,
  редактора, прокрутки с клавиатурой и выбора группы правил без падения приложения.
- Реальные проверки используют один слот подключения и изолированные данные,
  клиенты запускаются по очереди. Настройки сервера и документа не меняются.
- Один активный клиент на документ/ключ/экземпляр, только старый редактор Яндекса.
  На обеих сторонах нужна одинаковая обёртка `unified-openflux-aesgcm-v1`.
  Обычный upstream OpenFlux не является взаимозаменяемым с этой обёрткой.
- Только TCP/IPv4, без произвольного UDP и IPv6. DNS назначения идёт внутри
  зашифрованного TCP-туннеля; для запуска транспорта нужна исходная сеть.
  Прямая секретность и полный аудит безопасности не заявляются.
- Windows TUN остаётся недоступным; Local SOCKS и системный прокси доступны.
  Новые проверки физического телефона и установки поверх рабочего Windows-клиента
  не проводились. Подпись Windows Authenticode не настроена.
- Ограничения стабильной версии, включая периодические ошибки DNS/TLS при
  запуске Android VLESS, этим выпуском не объявляются исправленными.
