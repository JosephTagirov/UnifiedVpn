# Установка и обновление Windows

Начиная с 0.1.6 EXE открывает окно в цветах UnifiedVPN. Проверка Windows Installer
по постоянному UpgradeCode определяет режим:

- приложения нет — установить;
- найдена более ранняя версия или другая сборка той же версии — обновить;
- установлен этот же ProductCode — восстановить;
- установлена более новая версия — сохранить её без понижения.

ProductCode зависит от версии и номера сборки. Поэтому новая сборка той же
версии заменяет прежнюю через транзакцию MSI, без сообщения «другая версия
этого продукта уже установлена». Повторный запуск точно того же установщика
использует режим восстановления `REINSTALL=ALL REINSTALLMODE=vomus`.

Перед заменой EXE отправляет обычное сообщение закрытия только процессу
`UnifiedVPN.exe`, путь которого совпадает с зарегистрированным каталогом.
Приложение выполняет свою очистку VPN и прокси. Установщик ждёт завершения,
затем проверяет возможность открыть файлы приложения без совместного доступа.
Если файл всё ещё занят, остаётся кнопка «Повторить»; принудительное завершение
других VPN или удаление пользовательских настроек не выполняется.

С версии 0.1.7 MSI также сравнивает полный путь запущенного процесса с целевым
каталогом и зарегистрированными каталогами заменяемых продуктов. Общая проверка
по имени `UnifiedVPN.exe` удалена: запущенная переносная копия в другой папке
не мешает установке или восстановлению и остаётся открытой. Сам MSI содержит
проверку, поэтому она действует и при запуске пакета без окна EXE. Собственный
DTF custom action собирается SDK установленного WiX 3 и использует .NET Framework 4.
При занятом установленном приложении замена блокируется до удаления старого
продукта; окно показывает причину и предлагает повторить после закрытия из трея.

MSI запускается с `/qn /norestart REBOOT=ReallySuppress`; интерактивный интерфейс
принадлежит UnifiedVPN. Для системной установки остаётся стандартное подтверждение
Windows UAC. Глобальный `MsiSystemRebootPending` больше не блокирует установку.
Пакет также содержит `REBOOT=ReallySuppress`, а удаление старого продукта остаётся
внутри транзакции после `InstallInitialize`.

Обычное обновление не требует перезагрузки. Внешняя блокировка файла или сбой
Windows Installer отображаются с возможностью повторить операцию; код 3010
не скрывается как успешная полностью применённая замена. Журнал сохраняется в
`%LOCALAPPDATA%/UnifiedVPN/Setup`. Профили и подписки хранятся вне каталога
установки и сохраняются.

В установщик включён проверенный MSI с SHA-256. Проверка упаковки извлекает
его как данные, проверяет контрольную сумму, идентичность, диапазоны обновления,
порядок транзакции и отсутствие принудительной перезагрузки. Подпись APK для
Android остаётся прежней: Android распознаёт новый APK как обновление существующего
пакета, сохраняя данные; системное подтверждение установки остаётся.

Редакция владельца получает сведения из `/vpn-control/updates/owner.json`,
общая редакция — из `/vpn-control/updates/stable.json` и GitHub. Публичный GitHub
не служит резервом для установки редакции владельца: при недоступности её
канала приложение сохраняет текущую редакцию. Серверное дополнение маршрута
доступно в `tools/update-server/owner-feed.patch`; проверка независимости каналов
— в `test_owner_feed.py` рядом с ним. Секретов этот канал не содержит: установочные
файлы не заменяют аутентификацию в кабинете владельца.
