# Блокировка рекламы в UnifiedVPN

В клиент Android и Windows добавлен локальный фильтр рекламных и следящих
доменов. Он включён по умолчанию. Выключатель находится в **Настройки →
Настройки подключения → Блокировка рекламы**. Изменение применяется при следующем
подключении, без автоматического разрыва текущего сеанса.

Фильтр использует встроенный снимок HaGeZi Multi LIGHT. При старте соединения
список проверяется по SHA-256; подключение не зависит от загрузки списка с
интернета. Список обновляется вместе с приложением. При повреждении кэша он
восстанавливается из ресурсов. Метаданные, точный исходный commit и лицензия
находятся в `sharedUI/src/commonMain/composeResources/files/adblocking/`.

В текущем снимке 78 564 домена. На Windows отдельный локальный процесс
sing-box принимает трафик приложения/системного прокси/TUN, фильтрует его и
передаёт разрешённые соединения во внутренний SOCKS выбранного ядра.
На Android ту же конфигурацию использует локальный SOCKS-мост службы VPN:
`VpnService → tun2socks → sing-box с фильтром → SOCKS ядра → VPN-сервер`.
В режиме прокси вход начинается с локального SOCKS без `VpnService`.
Доступное имя домена берётся из DNS, SOCKS-запроса, HTTP Host или TLS SNI.

Список не загружается с сервера подписок при каждом соединении. Кнопка
«Обновить подписку» обновляет VPN-профили; новый снимок фильтра доставляется
обновлением приложения. HTTPS DNS (`dns.google` на `8.8.8.8:443`) для
движков без собственного DNS проходит внутри выбранного туннеля.

При проверке сервера 2026-11-03 отдельные AdGuardHome/dnsmasq не были активны,
а в действующем Xray не было рекламных правил блокировки. Таким образом,
наличие этого VPN-сервера само по себе не включает адблок для других клиентов.
Текущая блокировка UnifiedVPN выполняется на устройстве пользователя.

Рекламные DNS-запросы получают NXDOMAIN; обращения к известным рекламным доменам
через SOCKS также отклоняются. Обычный трафик и разрешённые DNS-запросы проходят
через прежний VPN-движок. Для WireGuard сохраняется обработка DNS исходным
движком с резолвером профиля. Для остальных движков используется тот же
зашифрованный DNS, что в прежнем Android DNS-мосте, внутри туннеля.
Отдельного прямого выхода, новых правил разделения трафика по странам, изменения
системного DNS, VPN сервера или глобального прокси нет. Фильтр работает только
для трафика, который уже проходит через UnifiedVPN; исключённые приложения
сохраняют прежнее поведение.

## Ограничения

- Фильтр не расшифровывает HTTPS и не устанавливает корневые сертификаты.
- Реклама с того же домена, что полезный контент, включая часть видеорекламы,
  может остаться. Полное удаление рекламы не гарантируется.
- Приложения со своим DoH/DoT и сохранёнными IP могут обходить DNS-фильтрацию;
  фильтрация известного имени в SOCKS/HTTP/TLS помогает, когда имя доступно.
- Пустые места после баннеров не скрываются. Сайты с ложным срабатыванием можно
  временно открыть после отключения фильтра и переподключения.
- При сбое процесса фильтра соединение завершается или восстанавливается
  службой; незаметного обхода включённого фильтра на сырой SOCKS-порт нет.

## Проверки

Нативный тест использует настоящий встроенный sing-box и подставной SOCKS-сервер
на loopback. Он проверяет блокировку домена и поддомена, DNS NXDOMAIN,
передачу обычного домена и похожего разрешённого имени через исходный SOCKS,
а также освобождение порта после остановки. Тест не меняет VPN или маршруты
компьютера. Переменная `UNIFIEDVPN_SING_BOX_TEST_BINARY` задаёт путь к ядру.
